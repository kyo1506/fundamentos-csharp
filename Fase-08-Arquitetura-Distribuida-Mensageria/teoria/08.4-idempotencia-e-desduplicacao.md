# 08.4: Idempotência e Desduplicação de Mensagens

> **Fase 08: Arquitetura Distribuída e Mensageria** · Aula 4
> Objetivo: garantir que mensagens duplicadas entregues pela rede não corrompam o estado do negócio ou executem efeitos colaterais repetidos.

---

## 1. O que é Idempotência?

Na matemática e na ciência da computação, uma operação é dita **idempotente** quando sua aplicação repetida produz o mesmo resultado final que uma única aplicação:

$$\forall x, \quad f(f(x)) = f(x)$$

No contexto de mensageria:
- Se uma mensagem `CobrarFatura(FaturaId: 100, Valor: R$ 50)` for entregue 3 vezes seguidas na fila, o cliente deve ser cobrado **exatamente uma vez**.
- As duas entregas subsequentes devem ser detectadas como duplicatas e ignoradas com segurança.

---

## 2. Por que Mensagens se Repetem na Rede?

1. **Garantia At-Least-Once:** Como vimos na aula anterior, sistemas confiáveis garantem entrega, o que implica que em falhas transitórias a mensagem será reenviada.
2. **Timeouts de Reconhecimento (ACK):** O consumidor processa com sucesso o pedido, mas a conexão TCP com o broker cai antes do envio do `Ack`. O broker entende que a mensagem não foi processada e a reencaminha para outro consumidor.
3. **Retentativas do Produtor:** Produtores com políticas de repetição automáticas.

## 3. Implementando o Padrão Consumidor Idempotente

A técnica mais robusta consiste em registrar cada `MessageId` (ou chave de idempotência de negócio) em uma tabela de controle antes ou durante a execução da transação de negócio:

```csharp
namespace EventBus.Distribuido.Core.Idempotencia;

public interface IStoreIdempotencia
{
    Task<bool> JaFoiProcessadaAsync(Guid messageId, CancellationToken ct = default);
    Task MarcarComoProcessadaAsync(Guid messageId, string nomeOperacao, CancellationToken ct = default);
}

public sealed class ConsumidorIdempotenteDecorator<T> : IConsumidorEvento<T> where T : class
{
    private readonly IConsumidorEvento<T> _decorado;
    private readonly IStoreIdempotencia _storeIdempotencia;
    private readonly Func<T, Guid> _obterMessageId;

    public ConsumidorIdempotenteDecorator(
        IConsumidorEvento<T> decorado,
        IStoreIdempotencia storeIdempotencia,
        Func<T, Guid> obterMessageId)
    {
        _decorado = decorado;
        _storeIdempotencia = storeIdempotencia;
        _obterMessageId = obterMessageId;
    }

    public async Task ConsumirAsync(T mensagem, CancellationToken ct = default)
    {
        var messageId = _obterMessageId(mensagem);

        // Se já processou, ignora a mensagem repetida sem erro
        if (await _storeIdempotencia.JaFoiProcessadaAsync(messageId, ct))
        {
            return;
        }

        // Executa o processamento real de negócio
        await _decorado.ConsumirAsync(mensagem, ct);

        // Registra como concluída
        await _storeIdempotencia.MarcarComoProcessadaAsync(messageId, typeof(T).Name, ct);
    }
}
```

## 4. Anti-exemplo: Depender de Flags Booleanas sem Atomicidade

```csharp
// ANTI-EXEMPLO: corrida de threads com duas mensagens duplicadas quase simultâneas!
var aluno = await _db.Alunos.FindAsync(id);
if (!aluno.Processado) // Ambas as threads leem 'false' ao mesmo tempo!
{
    aluno.Saldo += 100; // Saldo creditado DUAS vezes!
    aluno.Processado = true;
    await _db.SaveChangesAsync();
}
```

Para evitar condições de corrida (Race Conditions), utilize restrição única no banco de dados (`Unique Index`) sobre a coluna `MessageId` ou controle transacional com nível de isolamento apropriado.
