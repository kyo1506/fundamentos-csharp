# 02.2: Herança, Virtual/Override, Classes Abstratas e Membros Selados

> **Fase 02: Programação Orientada a Objetos + SOLID** · Aula 2
> Objetivo: dominar a reutilização e extensão de comportamento através de herança, sobrescrita de métodos com `virtual` e `override`, design com classes `abstract` e proteção de tipos com `sealed`.

---

## 1. O Conceito de Herança

Herança estabelece uma relação do tipo **"é um"** (is-a) entre duas classes:
- A **classe base** (superclasse ou mãe) fornece estrutura e comportamentos comuns.
- A **classe derivada** (subclasse ou filha) herda membros acessíveis e pode estender ou customizar o comportamento.

Em C#, uma classe pode herdar diretamente de **apenas uma** classe base (herança simples de implementação).

```csharp
public class Funcionario(string nome, string documento, decimal salarioBase)
{
    public string Nome { get; } = nome;
    public string Documento { get; } = documento;
    public decimal SalarioBase { get; } = salarioBase;

    public virtual decimal CalcularRemuneracao() => SalarioBase;
}

public class Gerente(string nome, string documento, decimal salarioBase, decimal bonus)
    : Funcionario(nome, documento, salarioBase)
{
    public decimal Bonus { get; } = bonus;

    public override decimal CalcularRemuneracao() => SalarioBase + Bonus;
}
```

## 2. A Tríade: `virtual`, `override` e `base`

- `virtual`: declara explicitamente na classe base que o método, propriedade ou indexador **pode** ser sobrescrito por classes derivadas.
- `override`: informa ao compilador que a classe derivada está fornecendo uma implementação especializada para um membro virtual ou abstrato.
- `base`: permite que a classe derivada invoque a implementação da classe mãe.

```csharp
public class Desenvolvedor(string nome, string documento, decimal salarioBase, int pullRequestsAprovados)
    : Funcionario(nome, documento, salarioBase)
{
    public int PullRequestsAprovados { get; } = pullRequestsAprovados;

    public override decimal CalcularRemuneracao()
    {
        var baseCalculada = base.CalcularRemuneracao();
        var premioProdutividade = PullRequestsAprovados * 50m;
        return baseCalculada + premioProdutividade;
    }
}
```

## 3. O Perigo de `new` (Method Shadowing / Ocultação de Membro)

Se você declarar um método com o mesmo nome na classe filha sem usar `override`, o compilador alertará sobre ocultação de membro. Usar a palavra-chave `new` silencia o aviso, mas **quebra o polimorfismo**:

```csharp
public class Base
{
    public void Exibir() => Console.WriteLine("Base");
}

public class Derivada : Base
{
    public new void Exibir() => Console.WriteLine("Derivada");
}

Base obj = new Derivada();
obj.Exibir(); // Imprime "Base" (porque não houve sobrescrita dinâmica na vtable)!
```

> Regra: prefira sempre `virtual`/`override`. Quase nunca use `new` em métodos de negócio.

## 4. Classes e Métodos Abstratos (`abstract`)

Uma classe `abstract` não pode ser instanciada diretamente (`new`). Ela serve como fundação conceitual e pode conter:
- Métodos e propriedades concretos com implementação.
- Métodos e propriedades abstratos (sem corpo), que **obrigam** a classe filha não-abstrata a implementar via `override`.

```csharp
public abstract class Notificacao(string destinatario)
{
    public string Destinatario { get; } = destinatario;
    public DateTime CriadaEm { get; } = DateTime.UtcNow;

    // Método abstrato: filhas DEVEM implementar
    public abstract bool Enviar(string mensagem);
}

public class NotificacaoEmail(string email) : Notificacao(email)
{
    public override bool Enviar(string mensagem)
    {
        Console.WriteLine($"[Email para {Destinatario}]: {mensagem}");
        return true;
    }
}

public class NotificacaoSms(string telefone) : Notificacao(telefone)
{
    public override bool Enviar(string mensagem)
    {
        Console.WriteLine($"[SMS para {Destinatario}]: {mensagem}");
        return true;
    }
}
```

## 5. Classes e Métodos Selados (`sealed`)

O modificador `sealed` impede que outros desenvolvedores herdem da classe ou sobrescrevam um método específico:

```csharp
public sealed class ConfiguracaoSistema
{
    public string Ambiente { get; init; } = "Produção";
}

// public class CustomConfig : ConfiguracaoSistema {} // Erro de compilação!
```

### Vantagens do `sealed`
- **Segurança e Imutabilidade:** garante que contratos e comportamentos críticos não sofram alterações indevidas.
- **Desempenho no .NET:** o compilador JIT e o runtime podem desvirtualizar chamadas de método (devirtualization) e aplicar inlining agressivo, eliminando o custo da vtable.
