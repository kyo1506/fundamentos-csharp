# Lição 07.2: Pipelines Assíncronos com System.Threading.Channels

O padrão **Produtor-Consumidor (Producer-Consumer)** é fundamental para desacoplar a taxa de ingestão de dados da taxa de processamento. No .NET moderno, o namespace `System.Threading.Channels` é a ferramenta de primeira escolha para construir filas assíncronas concorrentes de alto rendimento.

---

## 1. Por Que Não Usar BlockingCollection ou Filas Clássicas?

- `Queue<T>` com `lock`: Bloqueia threads de forma síncrona, provocando contenção e chaveamento de contexto no sistema operacional.
- `BlockingCollection<T>`: Eficiente para threads dedicadas clássicas, mas baseada em primitivas bloqueantes do SO que não se integram naturalmente ao modelo `async/await`.
- `Channel<T>`: Projetado do zero para ser **totalmente assíncrono**, com alocação quase nula, integração perfeita com `ValueTask` e suporte a fluxos contínuos via `IAsyncEnumerable`.

---

## 2. Tipos de Canais: Unbounded vs. Bounded

Podemos criar dois tipos de canais com a classe estática `Channel`:

### A. Canal Ilimitado (Unbounded)
Não possui limite de capacidade. O produtor nunca é pausado, gravando itens à medida que surgem.
- **Risco:** Se o consumidor for mais lento que o produtor, o canal cresce indefinidamente na memória RAM até derrubar o processo com `OutOfMemoryException`.

```csharp
Channel<Dado> canal = Channel.CreateUnbounded<Dado>();
```

### B. Canal Limitado (Bounded) com Backpressure
Possui capacidade máxima estrita. Quando o canal atinge o limite, uma estratégia de **Backpressure (Contrapressão)** é ativada para proteger a memória:

```csharp
var opcoes = new BoundedChannelOptions(capacidade: 1000)
{
    FullMode = BoundedChannelFullMode.Wait, // Pausa o produtor de forma assíncrona até surgir espaço
    SingleWriter = false,                  // Múltiplos produtores concorrentes
    SingleReader = false                   // Múltiplos consumidores concorrentes
};

Channel<Dado> canal = Channel.CreateBounded<Dado>(opcoes);
```

### Modos de Tratamento Quando o Canal Está Cheio (FullMode)
- `Wait`: O método `WriteAsync` aguarda de forma não-bloqueante até que um consumidor libere vaga.
- `DropOldest`: Remove o item mais antigo da fila para acomodar o novo (útil para telemetria em tempo real onde dados antigos perdem valor).
- `DropNewest`: Descarta o item mais recente.
- `DropWrite`: Descarta o item que estava tentando entrar.

## 3. Implementando um Pipeline Produtor-Consumidor Completo

```csharp
using System.Threading.Channels;

public class PipelineEventos
{
    private readonly Channel<string> _channel;

    public PipelineEventos(int capacidade = 500)
    {
        var opcoes = new BoundedChannelOptions(capacidade)
        {
            FullMode = BoundedChannelFullMode.Wait,
            SingleWriter = true,
            SingleReader = true
        };
        _channel = Channel.CreateBounded<string>(opcoes);
    }

    // Produtor assíncrono
    public async Task ProduzirMensagensAsync(IEnumerable<string> itens, CancellationToken ct)
    {
        foreach (var item in itens)
        {
            // Escreve assincronamente respeitando o backpressure
            await _channel.Writer.WriteAsync(item, ct);
        }

        // Sinaliza aos consumidores que não haverá mais dados
        _channel.Writer.Complete();
    }

    // Consumidor assíncrono
    public async Task ConsumirMensagensAsync(CancellationToken ct)
    {
        // Consome enquanto o canal tiver itens ou não for fechado
        await foreach (string mensagem in _channel.Reader.ReadAllAsync(ct))
        {
            // Processa a mensagem
            Console.WriteLine($"Processado: {mensagem}");
        }
    }
}
```

## 4. Orquestrando Múltiplos Consumidores em Paralelo

Para cargas de trabalho pesadas de CPU ou IO, podemos disparar múltiplos consumidores concorrentes que competem pela mesma ponta de leitura `ChannelReader`:

```csharp
public async Task IniciarProcessamentoParaleloAsync(Channel<Dado> canal, int totalConsumidores, CancellationToken ct)
{
    var tarefasConsumidores = Enumerable.Range(1, totalConsumidores)
        .Select(workerId => Task.Run(async () =>
        {
            await foreach (var dado in canal.Reader.ReadAllAsync(ct))
            {
                await ProcessarItemAsync(workerId, dado, ct);
            }
        }, ct));

    await Task.WhenAll(tarefasConsumidores);
}
```

### Vantagens do Pipeline com Channels
1. **Distribuição Equilibrada de Carga:** Os workers consomem sob demanda no ritmo exato de sua capacidade.
2. **Uso Previsível de Memória:** O tamanho do buffer é fixo e conhecido previamente.
3. **Desligamento Gracioso (Graceful Shutdown):** Chamar `.Complete()` no Writer faz com que todos os consumidores processem os itens restantes e finalizem suas tarefas de forma limpa.
