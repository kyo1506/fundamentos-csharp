# Lição 07.4: Metaprogramação, Source Generators e Native AOT

A evolução moderna do .NET substituiu o uso pesado de Reflection em tempo de execução por técnicas de **metaprogramação estática em tempo de compilação**. Essa mudança de paradigma possibilita binários minúsculos, tempos de inicialização imediatos e verificação rigorosa antes da implantação.

---

## 1. O Fim da Reflexão em Ambientes Cloud-Native

Por mais de uma década, frameworks .NET dependeram de `Reflection` para:
- Inspecionar propriedades para serialização JSON.
- Descobrir rotas e endpoints de controllers.
- Injetar dependências via contêineres IoC.

### Os Três Grandes Problemas da Reflexão
1. **Cold Start Lento:** No primeiro acesso a um microsserviço serverless, escanear assemblies pode consumir segundos preciosos.
2. **Incompatibilidade com Trimming:** O processo de remoção de código não utilizado (tree shaking) não sabe quais métodos são chamados dinamicamente via reflexão por strings, correndo o risco de apagá-los do binário final.
3. **Consumo de Memória:** O runtime precisa manter tabelas de metadados extensas na memória RAM.

---

## 2. A Arquitetura dos Roslyn Source Generators

Um **Source Generator** é um plugin do compilador C# (`Roslyn`) que inspeciona a sintaxe e a semântica do seu código durante o build e emite novos arquivos C# que são compilados junto com o projeto.

```
Código-Fonte C# ──────┐
                      ▼
             [ Compilador Roslyn ]
                      │
                      ▼
           [ Source Generator ] ── Gera código C# adicional
                      │                  │
                      ▼ ◄────────────────┘
             [ Binário Final / IL ]
```

### Exemplos Nativos no .NET
- **`System.Text.Json`:** Gera métodos de serialização específicos para cada DTO sem usar reflexão (`JsonSerializerContext`).
- **`System.Text.RegularExpressions`:** Compila expressões regulares em código C# puro (`[GeneratedRegex]`).
- **Logging Estruturado:** Gera código de log com `[LoggerMessage]` para evitar alocação de arrays de objetos e boxing.

---

## 3. O Que É Native AOT (Ahead-of-Time)?

No modelo tradicional do .NET:
- O compilador C# gera Intermediate Language (IL).
- Quando o programa é executado, o JIT (Just-In-Time Compiler) compila o IL para código de máquina da CPU da máquina hospedeira.

No modelo **Native AOT**:
- O compilador gera diretamente um executável nativo em código de máquina (ELF no Linux, PE no Windows, Mach-O no macOS).
- Não há IL, não há JIT e o runtime incluído é uma versão ultraleve (CoreRT/Native runtime).

### Comparação Prática

| Característica | JIT Tradicional | Native AOT |
|---|---|---|
| Tempo de inicialização | ~200 - 800 ms | < 10 ms |
| Consumo de memória base | ~35 - 70 MB | ~8 - 15 MB |
| Tamanho do contêiner Docker | ~120 - 250 MB | ~15 - 35 MB |
| Suporte a Reflection dinâmica | Total | Limitado (exige geração estática) |

## 4. Interceptors (C# 12+)

Interceptors são um recurso avançado de metaprogramação onde o compilador substitui estaticamente chamadas de método específicas por métodos alternativos:

```csharp
// Em tempo de compilação, o interceptor substitui a chamada direta:
app.MapGet("/api/v1/cursos", () => { ... });
// É substituída por código de roteamento direto gerado estaticamente,
// sem passar por árvores dinâmicas de delegates.
```

Isso garante que rotinas críticas rodem com zero camadas intermediárias de abstração.
