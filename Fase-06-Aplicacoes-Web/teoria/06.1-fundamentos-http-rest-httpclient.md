# Lição 06.1: Fundamentos HTTP, REST e Consumo com HttpClient

A web moderna e as arquiteturas de microsserviços comunicam-se fundamentalmente através do protocolo HTTP seguindo os princípios de estilo arquitetural REST (Representational State Transfer). Dominar a semântica HTTP e o consumo seguro de APIs externas é a base para qualquer engenheiro de software backend.

---

## 1. Verbos e Semântica HTTP

Cada requisição HTTP possui um método (verbo) que expressa a intenção da operação sobre o recurso identificado pela URI:

| Verbo | Propósito | Idempotente? | Seguro (Safe)? | Código Típico de Sucesso |
|---|---|---|---|---|
| `GET` | Recuperar a representação de um recurso. | Sim | Sim | `200 OK` |
| `POST` | Criar um novo recurso subordinado ou disparar ação. | Não | Não | `201 Created` |
| `PUT` | Substituir integralmente um recurso existente. | Sim | Não | `200 OK` ou `204 No Content` |
| `PATCH` | Atualizar parcialmente campos de um recurso. | Não | Não | `200 OK` ou `204 No Content` |
| `DELETE` | Remover um recurso. | Sim | Não | `204 No Content` ou `200 OK` |

- **Operação Segura (Safe):** A requisição é apenas de leitura e não altera o estado do servidor.
- **Operação Idempotente:** Executar a mesma requisição uma ou dez vezes seguidas produz exatamente o mesmo resultado no estado do sistema.

---

## 2. Códigos de Status HTTP Essenciais

Os códigos de status informam ao cliente o resultado do processamento da requisição:

### Família 2xx (Sucesso)
- `200 OK`: A requisição foi atendida e o recurso segue no corpo da resposta.
- `201 Created`: Novo recurso criado com sucesso. O cabeçalho `Location` deve apontar para a URI do novo recurso.
- `204 No Content`: Ação realizada com sucesso, mas a resposta não possui corpo (comum em exclusões ou atualizações).

### Família 4xx (Erro do Cliente)
- `400 Bad Request`: Parâmetros inválidos, campos obrigatórios ausentes ou payload corrompido.
- `401 Unauthorized`: O cliente não está autenticado (token ausente ou inválido).
- `403 Forbidden`: O cliente está autenticado, mas não possui permissão para acessar o recurso.
- `404 Not Found`: O recurso solicitado não existe na URI informada.
- `409 Conflict`: Conflito de regras de negócio (ex: tentativa de matricular aluno já cadastrado ou e-mail duplicado).

### Família 5xx (Erro do Servidor)
- `500 Internal Server Error`: Falha inesperada não tratada no servidor.
- `503 Service Unavailable`: O serviço está temporariamente indisponível ou sobrecarregado.

## 3. Anatomia de uma Requisição RESTful

```http
POST /api/v1/cursos HTTP/1.1
Host: api.faculdade.com
Content-Type: application/json
Authorization: Bearer eyJhbGciOiJIUzI1Ni...

{
  "titulo": "Arquitetura .NET",
  "precoBase": 899.90,
  "vagasTotais": 30
}
```

A resposta correspondente:

```http
HTTP/1.1 201 Created
Location: /api/v1/cursos/42
Content-Type: application/json

{
  "id": 42,
  "titulo": "Arquitetura .NET",
  "precoBase": 899.90,
  "vagasTotais": 30,
  "vagasOcupadas": 0
}
```

## 4. Consumo Seguro com HttpClient e IHttpClientFactory

Em aplicações .NET corporativas, instanciar manualmente `new HttpClient()` a cada requisição é um erro crítico:
- **Esgotamento de Sockets (Socket Exhaustion):** O descarte com `using var client = new HttpClient()` fecha o cliente lógico, mas a porta TCP subjacente permanece no estado `TIME_WAIT` pelo sistema operacional durante até 4 minutos. Sob alta concorrência, o servidor esgota suas portas disponíveis.

### A Solução: IHttpClientFactory
O `IHttpClientFactory` gerencia um pool inteligente de conexões (`HttpMessageHandler`), reutilizando conexões abertas e renovando conexões periodicamente para respeitar atualizações de DNS.

```csharp
// Registro no Program.cs
builder.Services.AddHttpClient("ViaCep", client =>
{
    client.BaseAddress = new Uri("https://viacep.com.br/ws/");
    client.Timeout = TimeSpan.FromSeconds(5);
});

// Consumo em serviço ou endpoint
public class CepService(IHttpClientFactory httpClientFactory)
{
    public async Task<EnderecoDto?> ConsultarCepAsync(string cep, CancellationToken ct)
    {
        var client = httpClientFactory.CreateClient("ViaCep");
        return await client.GetFromJsonAsync<EnderecoDto>($"{cep}/json/", ct);
    }
}
```

### Typed Clients (Clientes Tipados)
A forma mais elegante e coesa de encapsular chamadas de rede no .NET:

```csharp
public class PagamentoClient(HttpClient httpClient)
{
    public async Task<bool> ConfirmarPagamentoAsync(int matriculaId, decimal valor, CancellationToken ct)
    {
        var resposta = await httpClient.PostAsJsonAsync("v1/pagamentos", new { matriculaId, valor }, ct);
        return resposta.IsSuccessStatusCode;
    }
}

// Registro direto no container:
builder.Services.AddHttpClient<PagamentoClient>(client =>
{
    client.BaseAddress = new Uri("https://pagamentos.interno/");
});
```
