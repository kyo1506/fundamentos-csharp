# Lição 06.4: Acesso a Dados com Entity Framework Core (DbContext e Migrations)

O **Entity Framework Core (EF Core)** é o Object-Relational Mapper (ORM) moderno, extensível e multiplataforma do ecossistema .NET. Ele mapeia classes C# para tabelas relacionais em bancos de dados como PostgreSQL, SQL Server, MySQL e SQLite, permitindo consultas fortemente tipadas via LINQ.

---

## 1. O Conceito Central: DbContext e DbSet<T>

A classe `DbContext` representa uma sessão com o banco de dados, atuando como uma combinação dos padrões **Unit of Work** e **Repository**:
- Cada propriedade `DbSet<T>` representa uma tabela consultável e gravável.
- O `ChangeTracker` do `DbContext` rastreia alterações nos objetos carregados e emite comandos SQL mínimos (`INSERT`, `UPDATE`, `DELETE`) ao chamar `SaveChangesAsync()`.

```csharp
using Microsoft.EntityFrameworkCore;

public class AppDbContext : DbContext
{
    public AppDbContext(DbContextOptions<AppDbContext> options) : base(options) { }

    public DbSet<Aluno> Alunos => Set<Aluno>();
    public DbSet<Curso> Cursos => Set<Curso>();
    public DbSet<Matricula> Matriculas => Set<Matricula>();

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        base.OnModelCreating(modelBuilder);
        // Configurações via Fluent API
        modelBuilder.ApplyConfigurationsFromAssembly(typeof(AppDbContext).Assembly);
    }
}
```

## 2. Mapeamento com Fluent API (IEntityTypeConfiguration<T>)

Prefira Fluent API em arquivos de configuração separados em vez de poluir as entidades de domínio com atributos de banco de dados (`[Table]`, `[Column]`):

```csharp
using Microsoft.EntityFrameworkCore.Metadata.Builders;

public class CursoConfiguration : IEntityTypeConfiguration<Curso>
{
    public void Configure(EntityTypeBuilder<Curso> builder)
    {
        builder.ToTable("Cursos");

        builder.HasKey(c => c.Id);

        builder.Property(c => c.Titulo)
            .IsRequired()
            .HasMaxLength(150);

        builder.Property(c => c.PrecoBase)
            .HasPrecision(10, 2)
            .IsRequired();

        builder.Property(c => c.VagasTotais)
            .IsRequired();

        builder.Property(c => c.VagasOcupadas)
            .IsRequired();
    }
}
```

## 3. Consultas Assíncronas e Performance com AsNoTracking

Ao consultar dados apenas para leitura (ex: relatórios, APIs GET), o rastreamento do `ChangeTracker` é desnecessário e consome memória e ciclos de CPU. Utilize sempre `.AsNoTracking()`:

```csharp
public async Task<IReadOnlyList<CursoDto>> ListarCursosDisponiveisAsync(AppDbContext db, CancellationToken ct)
{
    return await db.Cursos
        .AsNoTracking()
        .Where(c => c.VagasOcupadas < c.VagasTotais)
        .OrderBy(c => c.Titulo)
        .Select(c => new CursoDto(c.Id, c.Titulo, c.PrecoBase, c.VagasTotais - c.VagasOcupadas))
        .ToListAsync(ct);
}
```

## 4. Inserções e Atualizações com Transações Implícitas

O método `SaveChangesAsync()` agrupa todas as modificações pendentes em uma transação atômica do banco de dados:

```csharp
public async Task EfetivarMatriculaAsync(AppDbContext db, int alunoId, int cursoId, decimal valor, CancellationToken ct)
{
    var curso = await db.Cursos.FirstOrDefaultAsync(c => c.Id == cursoId, ct)
        ?? throw new InvalidOperationException("Curso não encontrado.");

    curso.OcuparVaga(); // Atualiza entidade rastreada

    var matricula = new Matricula(0, alunoId, cursoId, valor, DateTimeOffset.UtcNow);
    await db.Matriculas.AddAsync(matricula, ct);

    // Emite UPDATE na tabela Cursos e INSERT na tabela Matriculas na mesma transação
    await db.SaveChangesAsync(ct);
}
```

## 5. Migrações (Migrations) do EF Core

As migrações mantêm o esquema do banco de dados em sincronia com o modelo C# em código:

```bash
# Adicionar uma nova migração baseada nas alterações do código
dotnet ef migrations add CriaTabelasIniciais

# Aplicar as migrações pendentes no banco de dados alvo
dotnet ef database update

# Gerar script SQL idempotente para ambientes de produção/CI
dotnet ef migrations script --idempotent --output deploy.sql
```
