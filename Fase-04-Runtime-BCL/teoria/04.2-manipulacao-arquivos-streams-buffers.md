# Lição 04.2: Manipulação de Arquivos, Streams e Buffers

O subsistema de Entrada e Saída (IO) do .NET é construído sobre o conceito de **Streams**: sequências contínuas de bytes independentes do destino físico subjacente (disco, rede, memória, pipes). Dominar streams e buffers permite processar gigabytes de dados com consumo de memória constante e baixo tempo de resposta.

---

## 1. Classes Utilitárias: File, Directory e Path

Para operações rápidas em arquivos pequenos e manipulação de diretórios, o namespace `System.IO` disponibiliza classes estáticas:

```csharp
using System.IO;

string pasta = Path.Combine(Directory.GetCurrentDirectory(), "relatorios");
Directory.CreateDirectory(pasta);

string arquivo = Path.Combine(pasta, "dados.txt");

// Escrita e leitura simples (arquivos pequenos)
await File.WriteAllTextAsync(arquivo, "Linha 1\nLinha 2");
string conteudo = await File.ReadAllTextAsync(arquivo);
bool existe = File.Exists(arquivo);
```

> **Aviso:** Métodos como `File.ReadAllTextAsync` ou `File.ReadAllBytesAsync` carregam o arquivo inteiro na memória de uma só vez. Para arquivos com dezenas de megabytes ou gigabytes, eles causam pressão severa no Garbage Collector e podem disparar `OutOfMemoryException`.

---

## 2. A Abstração Stream

A classe base abstrata `System.IO.Stream` define três operações centrais:
1. **Leitura:** Transferir bytes do stream para um buffer em memória (`ReadAsync`).
2. **Escrita:** Transferir bytes de um buffer para o stream (`WriteAsync`).
3. **Posicionamento:** Mover o cursor de leitura/escrita (`Seek`), quando suportado (`CanSeek == true`).

### Principais Implementações de Stream

| Classe | Descrição |
|---|---|
| `FileStream` | Leitura e escrita de bytes diretamente no sistema de arquivos. |
| `MemoryStream` | Stream em memória RAM, ideal para testes unitários ou pipelines de transformação. |
| `NetworkStream` | Stream sobre sockets de rede TCP. |
| `GZipStream` / `DeflateStream` | Streams decoradores para compressão/descompressão em trânsito. |
| `BufferedStream` | Adiciona camada intermediária de buffer para otimizar acessos repetidos. |

## 3. Leitura e Escrita Baseada em Texto: StreamReader e StreamWriter

Quando trabalhamos com dados textuais codificados (como UTF-8), utilizamos adaptadores sobre o stream de bytes:

```csharp
using System.Text;

public async Task ProcessarLogGrandeAsync(string caminho)
{
    // Abre stream sem carregar tudo na memória
    await using var fs = new FileStream(caminho, FileMode.Open, FileAccess.Read, FileShare.Read, bufferSize: 4096, useAsync: true);
    using var leitor = new StreamReader(fs, Encoding.UTF8);

    string? linha;
    int contador = 0;
    while ((linha = await leitor.ReadLineAsync()) != null)
    {
        contador++;
        // Processa cada linha individualmente
    }

    Console.WriteLine($"Total de linhas processadas: {contador}");
}
```

Para escrita:

```csharp
public async Task GravarRelatorioAsync(string caminho, IEnumerable<string> itens)
{
    await using var fs = new FileStream(caminho, FileMode.Create, FileAccess.Write, FileShare.None, bufferSize: 4096, useAsync: true);
    await using var escritor = new StreamWriter(fs, Encoding.UTF8);

    foreach (var item in itens)
    {
        await escritor.WriteLineAsync(item);
    }
    await escritor.FlushAsync(); // Garante envio dos dados para o disco
}
```

## 4. Cópia Eficiente de Streams: CopyToAsync

Copiar dados de uma origem para um destino (por exemplo, salvar download de rede em disco ou descompactar arquivo) é feito de forma assíncrona e tamponada com `CopyToAsync`:

```csharp
public async Task CompactarArquivoAsync(string origem, string destinoGz)
{
    await using var streamEntrada = File.OpenRead(origem);
    await using var streamSaida = File.Create(destinoGz);
    await using var streamCompactada = new System.IO.Compression.GZipStream(streamSaida, System.IO.Compression.CompressionLevel.Optimal);

    // Transfere os dados em blocos sem saturar a memória
    await streamEntrada.CopyToAsync(streamCompactada);
}
```

## 5. Buffers Modernos: Memory<byte>, ReadOnlyMemory<byte> e ArrayPool

Em código de alta performance, instanciar repetidamente novos arrays de bytes (`new byte[4096]`) a cada leitura polui o heap do GC. O .NET moderno oferece abstrações para reutilização de buffers:

```csharp
using System.Buffers;

public async Task LerEmBlocosComPoolAsync(Stream streamOrigem)
{
    // Aluga um buffer do pool compartilhado em vez de alocar no GC
    byte[] buffer = ArrayPool<byte>.Shared.Rent(4096);
    try
    {
        int bytesLidos;
        while ((bytesLidos = await streamOrigem.ReadAsync(buffer.AsMemory(0, 4096))) > 0)
        {
            // Processa o segmento de bytes lido
            ProcessarBloco(buffer.AsSpan(0, bytesLidos));
        }
    }
    finally
    {
        // Devolve obrigatoriamente o array para o pool
        ArrayPool<byte>.Shared.Return(buffer);
    }
}

private void ProcessarBloco(ReadOnlySpan<byte> dados)
{
    // Leitura rápida sem alocações
}
```

### Por Que Usar ArrayPool?
- Reduz drasticamente coletas de Gen 0 e Gen 1.
- Elimina o risco de alocar arrays gigantes no LOH repetidamente.
- Permite throughput contínuo em aplicações de ingestão de arquivos.
