# Lição 04.4: Programação Assíncrona Moderna (Task, async/await e CancellationToken)

A programação assíncrona no .NET baseia-se no Task-based Asynchronous Pattern (TAP). O objetivo principal de `async`/`await` em aplicações de servidor ou ferramentas CLI não é acelerar um cálculo de CPU em si, mas sim **liberar threads do sistema operacional** enquanto operações de Entrada e Saída (disco, banco de dados, rede HTTP) estão aguardando respostas.

---

## 1. O Que Acontece no async/await?

Quando um método marcado com `async` encontra uma instrução `await`:
1. Se a operação já estiver concluída de forma síncrona, a execução continua na mesma thread sem chaveamento de contexto.
2. Se a operação estiver pendente (ex: aguardando pacote de rede), a thread atual é devolvida ao `ThreadPool` do .NET para atender outras tarefas.
3. O compilador do C# reescreve o método como uma máquina de estados (`IAsyncStateMachine`).
4. Quando a operação de IO conclui, o sistema operacional notifica o runtime, que agenda a retomada da execução na próxima thread livre do pool.

```csharp
public async Task<string> BaixarDadosAsync(string url)
{
    using var http = new HttpClient();
    // Thread do pool liberada enquanto os bytes viajam pela rede
    string conteudo = await http.GetStringAsync(url);
    return conteudo;
}
```

## 2. Task vs. ValueTask

- `Task` e `Task<T>`: São objetos de referência alocados no heap gerenciado. Ideais para 95% dos cenários comuns de IO assíncrono.
- `ValueTask` e `ValueTask<T>`: Estruturas de valor (`struct`). Alocadas na pilha (sem gerar pressão no Garbage Collector). Indicadas quando uma operação assíncrona tem alta probabilidade de completar de forma síncrona (como leitura de buffer em cache de memória).

> **Aviso com ValueTask:** Uma instância de `ValueTask` não deve sofrer múltiplos `await`, nem ser aguardada concorrentemente com `Task.WhenAll`. Caso precise fazer isso, converta-a explicitamente com `.AsTask()`.

## 3. Concorrência e Composição: Task.WhenAll e Task.WhenAny

Ao disparar múltiplas operações independentes, não faça `await` sequencial em cada uma se elas puderem rodar em paralelo:

### Execução Sequencial (Lenta)
```csharp
// Leva o tempo total da soma das três operações
var r1 = await ObterDadosAsync(1);
var r2 = await ObterDadosAsync(2);
var r3 = await ObterDadosAsync(3);
```

### Execução Concorrente com Task.WhenAll (Rápida)
```csharp
// Dispara todas simultaneamente: o tempo total é limitado pela operação mais demorada
Task<Dado> t1 = ObterDadosAsync(1);
Task<Dado> t2 = ObterDadosAsync(2);
Task<Dado> t3 = ObterDadosAsync(3);

Dado[] resultados = await Task.WhenAll(t1, t2, t3);
```

### Timeout ou Corrida com Task.WhenAny
```csharp
Task<Dado> tarefa = ObterDadosAsync(1);
Task tempoLimite = Task.Delay(TimeSpan.FromSeconds(3));

Task concluida = await Task.WhenAny(tarefa, tempoLimite);
if (concluida == tempoLimite)
{
    throw new TimeoutException("A operação excedeu o tempo limite.");
}
Dado resultado = await tarefa;
```

## 4. Limitando Concorrência com SemaphoreSlim

Disparar milhares de requisições ou acessos a disco simultâneos pode esgotar conexões e travar o sistema. O `SemaphoreSlim` permite restringir o número de tarefas ativas concorrentemente:

```csharp
public async Task ProcessarLoteComLimiteAsync(IEnumerable<int> ids, int maximoConcorrente = 5)
{
    using var semaforo = new SemaphoreSlim(maximoConcorrente);
    var tarefas = ids.Select(async id =>
    {
        await semaforo.WaitAsync(); // Aguarda vaga disponível
        try
        {
            await ProcessarItemAsync(id);
        }
        finally
        {
            semaforo.Release(); // Libera a vaga para o próximo
        }
    });

    await Task.WhenAll(tarefas);
}
```

## 5. Cancelamento Cooperativo com CancellationToken

No .NET, o cancelamento é sempre **cooperativo**: uma tarefa não é abortada à força (o que deixaria memória corrompida e arquivos truncados). Em vez disso, o emissor sinaliza a intenção de cancelamento via `CancellationTokenSource`, e o método em execução verifica o token:

```csharp
public async Task ProcessarArquivoLongoAsync(Stream stream, CancellationToken cancellationToken)
{
    using var leitor = new StreamReader(stream);
    string? linha;

    while ((linha = await leitor.ReadLineAsync(cancellationToken)) != null)
    {
        // Verifica explicitamente se houve cancelamento
        cancellationToken.ThrowIfCancellationRequested();

        await ProcessarLinhaAsync(linha, cancellationToken);
    }
}
```

### Disparando Cancelamento

```csharp
using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(10)); // Timeout automático de 10s

try
{
    await ProcessarArquivoLongoAsync(stream, cts.Token);
}
catch (OperationCanceledException)
{
    Console.WriteLine("A operação foi cancelada de forma limpa pelo solicitante.");
}
```

## 6. Fluxos Assíncronos: IAsyncEnumerable<T>

Introduzido no C# 8, permite gerar sequências de valores sob demanda enquanto executa operações de IO assíncronas:

```csharp
public async IAsyncEnumerable<string> ObterLinhasRemotasAsync([EnumeratorCancellation] CancellationToken cancellationToken = default)
{
    for (int i = 1; i <= 5; i++)
    {
        await Task.Delay(100, cancellationToken); // Simula leitura remota
        yield return $"Linha {i} processada às {DateTime.Now:HH:mm:ss}";
    }
}

// Consumo com await foreach
await foreach (var linha in ObterLinhasRemotasAsync(cts.Token))
{
    Console.WriteLine(linha);
}
```

## 7. Anti-padrões Perigosos a Evitar

1. **`async void`:** Nunca use, exceto em event handlers de interface gráfica. Métodos `async void` não podem ser capturados em blocos `try/catch` e qualquer exceção não tratada derruba o processo inteiro imediatamente.
2. **`.Result` ou `.Wait()`:** Bloquear síncronamente em cima de uma `Task` (`tarefa.Result`) rouba uma thread do pool e causa deadlocks graves. Use sempre `await`.
3. **Esquecer de passar o `CancellationToken`:** Sempre propague o token para métodos internos que aceitam sobrecargas assíncronas com cancelamento.
