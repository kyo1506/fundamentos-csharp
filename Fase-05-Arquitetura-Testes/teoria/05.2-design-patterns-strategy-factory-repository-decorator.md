# Lição 05.2: Design Patterns Essenciais (Strategy, Factory, Repository, Decorator e Observer)

Padrões de Projeto (Design Patterns) são soluções reutilizáveis e consolidadas para problemas recorrentes no desenvolvimento de software orientado a objetos. Nesta lição, exploramos os cinco padrões mais comuns no ecossistema .NET corporativo.

---

## 1. Padrão Strategy (Estratégia)

O padrão Strategy define uma família de algoritmos, encapsula cada um deles em uma classe separada e os torna intercambiáveis em tempo de execução.

### Aplicação Real: Políticas de Desconto
Em vez de encadear múltiplos `if/else` ou `switch` gigantes na classe de pedidos ou matrículas:

```csharp
public interface IPoliticaDesconto
{
    decimal CalcularDesconto(decimal valorOriginal);
}

public class DescontoVeterano : IPoliticaDesconto
{
    public decimal CalcularDesconto(decimal valorOriginal) => valorOriginal * 0.20m;
}

public class DescontoPromocional : IPoliticaDesconto
{
    public decimal CalcularDesconto(decimal valorOriginal) => valorOriginal * 0.10m;
}

public class SemDesconto : IPoliticaDesconto
{
    public decimal CalcularDesconto(decimal valorOriginal) => 0m;
}
```

Uso:
```csharp
public class CalculadoraPreco(IPoliticaDesconto politica)
{
    public decimal ObterPrecoFinal(decimal precoBase)
    {
        return precoBase - politica.CalcularDesconto(precoBase);
    }
}
```

## 2. Padrão Factory Method (Fábrica)

O Factory Method encapsula a lógica de instanciação de objetos complexos, isolando o chamador da criação direta via `new`.

```csharp
public interface ICertificadoDigital
{
    string Emitir(string aluno, string curso);
}

public static class CertificadoFactory
{
    public static ICertificadoDigital Criar(string tipo) => tipo.ToLowerInvariant() switch
    {
        "pdf" => new CertificadoPdf(),
        "imagem" => new CertificadoPng(),
        _ => throw new ArgumentException($"Tipo de certificado desconhecido: {tipo}")
    };
}
```

## 3. Padrão Repository (Repositório)

O padrão Repository faz a mediação entre as camadas de domínio e de mapeamento de dados, atuando como uma coleção de objetos de domínio na memória.

```csharp
public interface IRepository<T, TId> where T : class
{
    Task<T?> ObterPorIdAsync(TId id, CancellationToken ct = default);
    Task<IReadOnlyList<T>> ListarTodosAsync(CancellationToken ct = default);
    Task AdicionarAsync(T entidade, CancellationToken ct = default);
    Task AtualizarAsync(T entidade, CancellationToken ct = default);
    Task RemoverAsync(TId id, CancellationToken ct = default);
}
```

### Benefício:
Permite desacoplar a lógica de negócio de comandos SQL específicos, tornando a aplicação simples de testar através de repositórios em memória (`InMemoryRepository`).

## 4. Padrão Decorator (Decorador)

O padrão Decorator anexa responsabilidades adicionais a um objeto dinamicamente sem alterar seu código-fonte ou recorrer à herança profunda.

### Aplicação Real: Repositório com Cache Transparente

```csharp
// Repositório concreto que acessa banco de dados lento
public class CursoSqlRepository : ICursoRepository
{
    public async Task<Curso?> ObterPorIdAsync(int id, CancellationToken ct)
    {
        // Consulta no banco de dados
        return await Task.FromResult(new Curso(id, "C# Avançado"));
    }
}

// Decorador que adiciona cache sem alterar a classe concreta
public class CachedCursoRepository(
    ICursoRepository inner,
    IMemoryCache cache) : ICursoRepository
{
    public async Task<Curso?> ObterPorIdAsync(int id, CancellationToken ct)
    {
        string chave = $"curso_{id}";
        if (cache.TryGetValue(chave, out Curso? cursoEmCache))
        {
            return cursoEmCache;
        }

        var curso = await inner.ObterPorIdAsync(id, ct);
        if (curso != null)
        {
            cache.Set(chave, curso, TimeSpan.FromMinutes(10));
        }

        return curso;
    }
}
```

O consumidor recebe uma interface `ICursoRepository` e não sabe (nem precisa saber) se os dados estão vindo do banco ou da memória.

## 5. Padrão Observer (Observador)

O padrão Observer define uma dependência um-para-muitos entre objetos, de modo que quando um objeto muda de estado, todos os seus dependentes são notificados automaticamente.

No C#, além de eventos nativos (`event EventHandler`), esse padrão é amplamente utilizado em arquiteturas de eventos de domínio (Domain Events) ou mensageria com barramento interno (Mediator / MediatR).

```csharp
public interface IDomainEventHandler<in TEvent>
{
    Task HandleAsync(TEvent evento, CancellationToken ct = default);
}

public record AlunoMatriculadoEvent(int AlunoId, int CursoId, DateTimeOffset OcorridoEm);

public class EnviarBoasVindasHandler : IDomainEventHandler<AlunoMatriculadoEvent>
{
    public Task HandleAsync(AlunoMatriculadoEvent evento, CancellationToken ct)
    {
        Console.WriteLine($"Disparando e-mail de boas-vindas para aluno {evento.AlunoId}");
        return Task.CompletedTask;
    }
}
```
