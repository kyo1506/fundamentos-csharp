# 00.10 — Depuração, erros comuns e testes de mesa

> **Fase 00** · Aula 10
> Objetivo: encontrar e corrigir bugs com método (debugger, leitura de erro, teste de mesa).

## 1. Os três tipos de problema
1. **Erro de compilação** — o código não compila. O compilador aponta arquivo/linha. Corrija a sintaxe/tipos.
2. **Erro de execução** (exceção) — compila, mas quebra ao rodar (ex.: dividir por zero, índice fora do array).
3. **Erro de lógica** — compila e roda, mas faz a coisa errada (o mais perigoso).

## 2. Ler um erro (stack trace) é uma habilidade

```
Unhandled exception. System.IndexOutOfRangeException: Index was outside the bounds of the array.
   at Program.<Main>$(String[] args) in /app/Program.cs:line 8
```
- **Tipo**: `IndexOutOfRangeException` → acessou índice inválido.
- **Mensagem**: descreve o problema.
- **Localização**: `Program.cs:line 8` → é lá que começou.

> Leia a mensagem inteira e procure a linha do **seu código** (as linhas de dentro do .NET
> normalmente não são o problema real).

## 3. Debugger (quebrar e inspecionar)

No VS Code/Rider:
1. **Breakpoint** — clique na margem de uma linha (bolinha vermelha).
2. Rode em modo **Debug** (F5) em vez de Run.
3. O programa **pausa** na linha. Inspecione **variáveis** no painel.
4. **Step Over (F10)**: executa a linha e vai para a próxima.
   **Step Into (F11)**: entra dentro da função chamada.
5. Use **Watch** para avaliar expressões.

Isso responde à pergunta *"mas o valor desta variável aqui é o quê?"* — a pergunta número 1
de quem depura.

## 4. Teste de mesa (desenhar o estado passo a passo)

Antes de qualquer código, rastreie "no papel". Ex.: `SomarDe1Ate(3)`:

| i | soma |
|---|------|
| 1 | 1 |
| 2 | 3 |
| 3 | 6 |

`return 6`. ✓

Teste de mesa é o método mais confiável para **lógica pura** — faça antes de rodar.

## 5. Erros comuns de iniciante (e como evitá-los)

| Erro | Por quê | Correção |
|------|---------|----------|
| `i <= arr.Length` no `for` | último índice é `Length-1` | `i < arr.Length` |
| Dividir `int/int` e "perder" casas | divisão inteira | usar `double`/`decimal` ou converter |
| Loop infinito | condição nunca vira falsa | garantir incremento/saída (`break`) |
| Comparar `string` com caixa errada | `==` diferencia caixa | `Equals(..., OrdinalIgnoreCase)` |
| `=` no lugar de `==` | atribuição | revisar |
| Não tratar entrada inválida | `Parse` lança | usar `TryParse` |
| Achar que mudou a `string` | string é imutável | atribuir o retorno: `s = s.ToUpper()` |
| Variável fora do escopo | declarada dentro de `{}` | declarar onde precisa |

## 6. `Console.WriteLine` para inspecionar (depuração "pobre", mas útil)

```csharp
int parcial = Soma(1, 2);
Console.WriteLine($"[debug] parcial = {parcial}");   // veja o valor
```

> Prefira o **debugger** (breakpoints) a encher de `Console.WriteLine`. Se usar print,
> remova antes de entregar o código.

## 7. Dividir o problema: "faça o código falhar pequeno"

1. Isole a função que erra.
2. Teste com o **menor caso** possível.
3. Confirme entrada/saída esperadas.
4. Aumente a complexidade devagar.

## 8. Exercícios

**Fácil — 1.** O código abaixo tem um bug de lógica. Encontre **sem rodar**, usando teste de mesa,
e depois corrija:
```csharp
static int SomaPares(int[] nums)
{
    int soma = 0;
    for (int i = 0; i <= nums.Length; i++)
        if (nums[i] % 2 == 0) soma += nums[i];
    return soma;
}
```

**Médio — 2.** Escreva uma função que deveria devolver a **quantidade** de números negativos
num array, mas você deve primeiro escrever o teste de mesa para `[-1,2,-3,4]` e então implementar.

**Desafiador — 3.** No debugger do seu editor, coloque breakpoints e observe o valor de cada
variável ao percorrer um `foreach`. Descreva o que o painel "Watch"/"Variables" mostra a cada
iteração.
