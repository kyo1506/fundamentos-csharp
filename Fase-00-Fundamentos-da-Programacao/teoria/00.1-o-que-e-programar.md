# 00.1 — O que é Programar?

> **Fase 00 — Fundamentos da Programação** · Aula 1
> Objetivo: entender o que é programar, o que é um algoritmo e como o C# chega do código ao executável.

## 1. O computador é "burro" — mas muito rápido

Um computador não "entende" nada: ele apenas executa, **na ordem**, um conjunto
limitadíssimo de instruções aritméticas e de movimentação de memória. A inteligência
aparente vem de nós: **organizar essas instruções para resolver um problema**.

Programar é **traduzir um problema do mundo real em uma sequência precisa de passos
que o computador consiga executar**.

### Analogia: a receita de bolo
Uma receita é um **algoritmo**:
1. Pegue os ingredientes (entrada).
2. Misture os secos.
3. Adicione os líquidos.
4. Asse a 180 °C por 40 min.
5. Sirva (saída).

Um algoritmo tem três propriedades essenciais:
- **Determinístico**: dado o mesmo início, o resultado é o mesmo.
- **Finito**: termina após um número de passos.
- **Bem definido**: cada passo não deixa dúvida.

## 2. Linguagem de programação ≠ máquina

O processador fala *linguagem de máquina* (bits). Escrever bits é inviável para humanos.
Então escrevemos em **linguagens de alto nível** (C#, Python, Java...) e um **compilador**
traduz para o que a máquina entende.

### O caminho do C#
```
Código-fonte (.cs)            →  compilador (Roslyn)       →  IL (linguagem intermediária)
     ↓
Common Language Runtime (CLR / dotnet)  →  executa a IL   →  instruções da CPU
```

- O **C#** é a linguagem (sintaxe que você escreve).
- O **.NET** é a plataforma/ecossistema (runtime, bibliotecas, ferramentas).
- O **CLR** é o "motor" que executa o programa e cuida de memória, threads etc.

### Compilação AOT vs JIT
- **JIT** (Just-In-Time): o .NET compila a IL para código de máquina **na hora em que roda**.
  É o padrão — permite otimizações em tempo de execução.
- **AOT** (Ahead-Of-Time, `NativeAOT`): compila **antes** de rodar, gerando executável nativo
  (menor, inicia rápido). Use quando precisar de deploy mínimo.
- (Você não precisa decorar isso agora; só saiba que *existe*.)

## 3. Sintaxe, semântica e lógica

Três níveis de erro/atenção ao programar:
1. **Sintaxe**: a "gramática" da linguagem. `int x = 10;` certo; `int x = ;` erra na compilação.
2. **Semântica**: o significado. `int x = "abc";` é sintaticamente estranho e não compila (tipo errado).
3. **Lógica**: seu programa compila e roda, mas faz o resultado errado (bug).

> Regra de ouro: **o computador faz exatamente o que você mandou — não o que você queria.**

## 4. Pensar em passos (decomposição)

Todo problema grande deve ser **decomposto** em problemas menores (funções), cada um
fazendo **uma coisa só**. Veremos isso em Aula 00.10 (funções) e com força em OO/SOLID.

**Anti-exemplo:** tentar resolver tudo num único bloco gigante de código.
**Bom exemplo:** separar em *entrada → processamento → saída*, e cada processamento em função.

## 5. Exercícios de fixação

**Fácil — 1.** Escreva, em português (pseudocódigo), o algoritmo para:
(a) decidir se um número é par ou ímpar;
(b) calcular a média de três provas e dizer se o aluno passou (média ≥ 6).

**Médio — 2.** Desenhe um **fluxograma** (ou lista numerada) do algoritmo de uma
máquina de café com opções: "café preto" ou "café com leite", e pagamento válido/não.

**Desafiador — 3.** Um problema "fácil para humano, difícil para máquina"? Cite um
exemplo de tarefa que seja **trivial** para uma pessoa e exija passos longos numa
máquina (dica: reconhecer rostos, entender sarcasmo, amarrar cadarço).

> A resposta certa de programação costuma ser: **dividir, nomear bem e testar cada parte.**
