# 01.3 — Números: `decimal` para Dinheiro, Ponto Flutuante e `Math`

> **Fase 01 — C# Básico: a linguagem em profundidade** · Aula 3
> Objetivo: entender a representação binária de números, por que float/double falham em cálculos financeiros, como o tipo decimal opera e como utilizar as funções matemáticas e de arredondamento com rigor.

---

## 1. A Ilusão do Ponto Flutuante (IEEE 754)

Os tipos `float` (32 bits) e `double` (64 bits) seguem o padrão IEEE 754. Eles representam números em base 2 (binária) fracionária.

Assim como $1/3$ não pode ser representado perfeitamente em base decimal ($0.3333...$), frações decimais simples como $0.1$ ou $0.2$ **não têm representação binária finita**:

```csharp
double a = 0.1;
double b = 0.2;
double soma = a + b;

Console.WriteLine(soma); // 0.30000000000000004
Console.WriteLine(soma == 0.3); // False!
```

> ❌ **NUNCA** utilize `float` ou `double` para:
> - Dinheiro, contas bancárias, tributos e moedas
> - Estoques e balanços contábeis
> - Comparações diretas de igualdade (`==`)

---

## 2. O Tipo `decimal` (128 bits)

O tipo `decimal` (System.Decimal) armazena números em **base 10** através de inteiros escalonados por potências de 10:
- **Tamanho:** 128 bits (16 bytes).
- **Precisão:** 28 a 29 dígitos significativos.
- **Intervalo:** de $\pm 1.0 \times 10^{-28}$ até $\pm 7.9228 \times 10^{28}$.
- **Sufixo:** `m` ou `M`.

```csharp
decimal preco1 = 0.1m;
decimal preco2 = 0.2m;
decimal total = preco1 + preco2;

Console.WriteLine(total == 0.3m); // True! Sem erros residuais
```

### Trade-off de Performance
Operações com `decimal` são executadas majoritariamente via software pelo runtime, sendo de 5x a 15x mais lentas que instruções de `double` (que rodam direto na FPU do hardware). Portanto:
- Use `decimal` para regras de negócio e finanças.
- Use `float`/`double` para jogos, simulações físicas, inteligência artificial e gráficos.

## 3. Arredondamento Rigoroso (`Math.Round` e `MidpointRounding`)

Por padrão, `Math.Round` no .NET adota o **Banker's Rounding** (Arredondamento Bancário / `ToEven`): se o dígito descartado estiver exatamente na metade (.5), arredonda para o número par mais próximo.

```csharp
Console.WriteLine(Math.Round(2.5m)); // 2  (2 é par)
Console.WriteLine(Math.Round(3.5m)); // 4  (4 é par)
```

Para a regra comercial comum no Brasil (arredondar .5 sempre para cima, afastando de zero):

```csharp
decimal valor = 2.555m;
decimal comercial = Math.Round(valor, 2, MidpointRounding.AwayFromZero); // 2.56
decimal bancario = Math.Round(valor, 2, MidpointRounding.ToEven);       // 2.56
```

## 4. Métodos Úteis de `System.Math`

```csharp
decimal preco = 149.99m;

// Teto e piso
decimal teto = Math.Ceiling(preco); // 150m (menor inteiro maior ou igual)
decimal piso = Math.Floor(preco);   // 149m (maior inteiro menor ou igual)
decimal trunc = Math.Truncate(preco); // 149m (descarta decimais)

// Limitação de faixa (Clamp - introduzido no .NET Core / moderno)
int estoque = Math.Clamp(150, 0, 100); // 100 (limita entre min e max)

// Potência e Raiz
double raiz = Math.Sqrt(144); // 12
double pot = Math.Pow(2, 8);   // 256
```

## 5. `checked` e `unchecked`: Lidando com Overflow

Por padrão no C#, operações inteiras que ultrapassam os limites sofrem *overflow silencioso* (`unchecked`):

```csharp
int max = int.MaxValue; // 2.147.483.647
int estourou = max + 1; // -2.147.483.648 (sem erro!)

// Para forçar exceção em caso de estouro:
try
{
    checked
    {
        int seguro = max + 1; // Lança OverflowException
    }
}
catch (OverflowException)
{
    Console.WriteLine("Detecção de estouro aritmético!");
}
```
