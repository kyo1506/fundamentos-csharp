# 01.5 — Exceções e Tratamento de Erros no C#

> **Fase 01 — C# Básico: a linguagem em profundidade** · Aula 5
> Objetivo: dominar a hierarquia de exceções do .NET, a semântica correta de try/catch/finally, filtros com when, como evitar a destruição do stack trace com throw, e criação de exceções de domínio.

---

## 1. A Filosofia de Exceções no .NET

Exceções são destinadas a **condições excepcionais** (falha de rede, disco cheio, violação de regra de negócio crítica, estado inconsistente) e não para fluxo regular de controle:

```
                  System.Object
                        ↓
                 System.Exception
            ┌───────────┴───────────┐
            ↓                       ↓
    System.SystemException    System.ApplicationException (Legado)
    ├── ArgumentException
    │   ├── ArgumentNullException
    │   └── ArgumentOutOfRangeException
    ├── InvalidOperationException
    ├── KeyNotFoundException
    └── FormatException
```

> ⚠️ **Princípio:** se a situação acontece rotineiramente (ex.: usuário digitou letra no campo de idade), use o padrão **Tester-Doer** ou **Try-Parse** (`int.TryParse`), evitando o custo de desenrolar a pilha (stack unwinding) que custa milhares de ciclos de CPU.

## 2. Blocos `try`, `catch`, `finally`

```csharp
FileStream? stream = null;
try
{
    stream = File.OpenRead("dados.bin");
    // processa o arquivo...
}
catch (FileNotFoundException ex)
{
    Console.WriteLine($"Arquivo ausente: {ex.FileName}");
}
catch (IOException ex)
{
    Console.WriteLine($"Erro de I/O geral: {ex.Message}");
}
finally
{
    // O bloco finally SEMPRE executa, mesmo se houver exceção ou return no try
    stream?.Dispose();
}
```

## 3. A Pegadinha Mortal: `throw` vs `throw ex`

Esta é uma das perguntas mais comuns em entrevistas técnicas e causas de bugs em produção:

```csharp
try
{
    MetodoComFalha();
}
catch (Exception ex)
{
    // ❌ PÉSSIMO: 'throw ex' REINICIA o Stack Trace!
    // A linha original onde o erro ocorreu dentro de MetodoComFalha() é perdida para sempre!
    // throw ex;

    // ✅ CORRETO: 'throw' PRESERVA o Stack Trace original intacto desde a origem:
    throw;
}
```

Caso queira encapsular a exceção em uma de nível superior (ex.: exceção de domínio), passe a original como `innerException`:

```csharp
catch (SqlException ex)
{
    // ✅ Preserva a causa raiz como innerException:
    throw new RepositorioException("Falha ao consultar base de dados", ex);
}
```

## 4. Filtros de Exceção com `when`

Permite capturar uma exceção condicionalmente sem desenrolar a pilha antecipadamente:

```csharp
try
{
    ChamarServicoExterno();
}
catch (HttpRequestException ex) when (ex.StatusCode == System.Net.HttpStatusCode.NotFound)
{
    Console.WriteLine("Recurso não existe na API");
}
catch (HttpRequestException ex) when (ex.StatusCode == System.Net.HttpStatusCode.Unauthorized)
{
    Console.WriteLine("Credencial expirada");
}
```

## 5. Exceções Customizadas de Domínio

Para expressar regras de negócio com clareza:

```csharp
public class SaldoInsuficienteException : Exception
{
    public decimal SaldoAtual { get; }
    public decimal ValorTentado { get; }

    public SaldoInsuficienteException(decimal saldoAtual, decimal valorTentado)
        : base($"Saldo de {saldoAtual:C} insuficiente para saque de {valorTentado:C}.")
    {
        SaldoAtual = saldoAtual;
        ValorTentado = valorTentado;
    }
}
```

## 6. Exercícios de Fixação

**Fácil — 1.** Crie um método `CalcularDivisaoSegura(int numerador, int denominador)` que captura `DivideByZeroException` e retorna uma mensagem amigável sem deixar o programa quebrar.

**Médio — 2.** Escreva um método `ProcessarTransacao(decimal saldo, decimal saque)` que lança `ArgumentOutOfRangeException` se o saque for menor ou igual a zero, e lança a exceção customizada `SaldoInsuficienteException` caso o saque ultrapasse o saldo.

**Desafiador — 3.** Escreva uma função com filtro `catch (Exception ex) when (...)` que só captura a exceção se o método auxiliar de log `RegistrarErro(ex)` retornar `true`. Explique a diferença de comportamento de pilha (stack trace inspection) em filtros de exceção.
