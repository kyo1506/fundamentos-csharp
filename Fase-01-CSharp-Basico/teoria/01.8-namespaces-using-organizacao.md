> Objetivo: dominar o empacotamento lógico do C#, diretivas using globais e estáticas, namespaces com escopo de arquivo e boas práticas de arquitetura física de soluções.

## 1. Namespaces: Organização Lógica sem Ambiguidade

Um `namespace` agrupa tipos relacionados e previne colisões de nomes (ex.: `System.Threading.Timer` vs `System.Timers.Timer`).

### File-Scoped Namespaces (C# 10+)
Reduz o nível de indentação visual de todo o arquivo:

```csharp
// Estilo clássico (com chaves e indentação desnecessária):
// namespace MeuProjeto.Servicos
// {
//     public class MinhaClasse { }
// }

// ✅ Estilo moderno: File-scoped namespace
namespace MeuProjeto.Servicos;

public class MinhaClasse
{
    // ...
}
```

## 2. Diretivas `using` Avançadas

### Global Using (C# 10+)
Permite declarar usings que valem para **todos** os arquivos do projeto C#:

```csharp
// Arquivo Usings.cs na raiz do projeto:
global using System;
global using System.Collections.Generic;
global using System.Text;
```

### Using Static
Importa os membros estáticos de uma classe diretamente para o escopo:

```csharp
using static System.Math;

// Em vez de Math.Sqrt(144) ou Math.PI:
double raio = Sqrt(144);
double circ = 2 * PI * raio;
```

### Alias de Namespace ou Tipo
Resolve conflitos imediatos de nomenclatura:

```csharp
using DataTimer = System.Timers.Timer;
using ThreadTimer = System.Threading.Timer;
```

---

## 3. O Modificador `static`

- **Classes Estáticas (`static class`):** não podem ser instanciadas nem herdadas. Contêm apenas membros estáticos e servem tipicamente como classes utilitárias ou recipientes de métodos de extensão.
- **Construtor Estático (`static Construtor()`):** executado uma única vez pelo CLR antes de qualquer membro da classe ser acessado.
- **Membros Estáticos:** pertencem ao tipo e compartilham o mesmo estado entre todas as instâncias e threads (cuidado com concorrência e thread safety!).
