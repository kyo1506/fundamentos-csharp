## 1. O Modelo de Memória do .NET: Stack vs Heap

No ecossistema .NET, a memória gerenciada pelo CLR (Common Language Runtime) é dividida conceitualmente em duas áreas principais de alocação de dados:

### A Stack (Pilha)
- **Como funciona:** estrutura de pilha LIFO (Last In, First Out), altamente otimizada pelo processador através do registrador de stack pointer.
- **Ciclo de vida:** escopo de execução da função/bloco. Quando uma thread entra em um método, aloca o stack frame; quando o método retorna, o ponteiro de pilha é ajustado e toda a memória é liberada instantaneamente sem intervenção do Garbage Collector (GC).
- **O que guarda:** valores de tipos por valor declarados localmente e **ponteiros/endereços** para objetos alocados na Heap.

### A Heap (Monte / Memória Dinâmica)
- **Como funciona:** área contígua de memória onde objetos de tamanho variável ou vida longa residem.
- **Ciclo de vida:** gerenciada pelo Garbage Collector (GC). Objetos continuam vivos enquanto houver raízes (roots) apontando para eles. A desalocação não é imediata e envolve fases de marcação (mark), varredura (sweep) e compactação (compact).
- **O que guarda:** instâncias de tipos por referência (`class`, `string`, arrays, delegates) e tipos por valor em caixas (boxed).

```
  STACK (Rápida, escopo local)            HEAP (Dinâmica, gerenciada pelo GC)
┌───────────────────────────────┐        ┌───────────────────────────────────┐
│ int idade = 30                │        │                                   │
│ double taxa = 0.05            │        │ Objeto Cliente                    │
│ Cliente c ────────────────────┼───────>│ { Nome = "Maria", Saldo = 1500m } │
│ (endereço de memória 8 bytes) │        │                                   │
└───────────────────────────────┘        └───────────────────────────────────┘
```

## 2. Tipos por Valor (Value Types)

Herdeiros diretos de `System.ValueType` (que por sua vez descende de `System.Object`):
- Tipos numéricos primitivos: `sbyte, byte, short, ushort, int, uint, long, ulong, float, double, decimal`
- Booleanos e caracteres: `bool, char`
- Estruturas de dados e datas: `struct`, `enum`, `DateTime`, `DateOnly`, `TimeOnly`, `TimeSpan`, `Guid`
- Tuplas por valor: `(int, string)`

### Semântica de Cópia
Quando você atribui uma variável de tipo por valor a outra ou a passa por parâmetro (sem modificadores `ref`/`in`/`out`), uma **cópia binária completa** de seu conteúdo é realizada:

```csharp
public struct Ponto
{
    public int X;
    public int Y;
}

Ponto p1 = new Ponto { X = 10, Y = 20 };
Ponto p2 = p1; // Cópia independente dos bytes de p1
p2.X = 99;

Console.WriteLine(p1.X); // Imprime 10! p1 permanece intocado
Console.WriteLine(p2.X); // Imprime 99
```

## 3. Tipos por Referência (Reference Types)

Tipos que herdam diretamente de `System.Object` (exceto `System.ValueType`):
- Classes: `class`
- Textos: `string` (tipo por referência com comportamento imutável)
- Estruturas de dados dinâmicas: arrays (`int[]`), coleções (`List<T>`, `Dictionary<K,V>`)
- Interfaces e delegates: `interface`, `Action`, `Func`

### Semântica de Apontamento
A variável contém apenas a **referência** (o ponteiro, 4 bytes em 32-bit ou 8 bytes em 64-bit) para o local onde o payload do objeto se encontra na Heap:

```csharp
public class ContaBancaria
{
    public decimal Saldo { get; set; }
}

ContaBancaria c1 = new ContaBancaria { Saldo = 1000m };
ContaBancaria c2 = c1; // Copia apenas o ponteiro, ambos apontam para o mesmo objeto na Heap
c2.Saldo = 2500m;

Console.WriteLine(c1.Saldo); // Imprime 2500m!
Console.WriteLine(object.ReferenceEquals(c1, c2)); // True: mesmo endereço
```

## 4. Boxing e Unboxing: O Custo Oculto

### O que é Boxing?
O processo de converter um **tipo por valor** em um **tipo por referência** (`object` ou uma `interface` que o tipo implementa).
1. O CLR aloca um novo bloco na Heap (overhead de MethodTable pointer + SyncBlockIndex = 16 a 24 bytes adicionais).
2. O valor da Stack é copiado para dentro do novo objeto alocado.
3. O ponteiro para esse novo objeto é retornado.

```csharp
int numero = 42;
object obj = numero; // BOXING: alocação desnecessária na Heap!
```

### O que é Unboxing?
A operação inversa: extrair o valor contido na caixa da Heap de volta para uma variável de valor na Stack.
1. O runtime verifica se o tipo do objeto na Heap é compatível com o tipo de destino (caso contrário, lança `InvalidCastException`).
2. O conteúdo dos bytes internos é copiado de volta para a Stack.

```csharp
int deVolta = (int)obj; // UNBOXING: verificação de tipo + cópia
```

### O Impacto em Desempenho
Boxing em loops cria centenas de milhares de pequenas alocações que sobrecarregam a Geração 0 (Gen 0) do Garbage Collector, causando pausas (GC pauses):

```csharp
// ❌ PÉSSIMO: coleções não-genéricas causam boxing em cada inserção
System.Collections.ArrayList lista = new();
for (int i = 0; i < 1_000_000; i++)
{
    lista.Add(i); // Boxing de 1 milhão de inteiros! Aloca ~24MB a 32MB de lixo
}

// ✅ EXCELENTE: coleções genéricas evitam boxing completamente
List<int> listaEficiente = new(1_000_000);
for (int i = 0; i < 1_000_000; i++)
{
    listaEficiente.Add(i); // Zero boxing, memória contígua
}
```

## 5. Passagem de Parâmetros: `ref`, `in`, `out`

Por padrão, tipos por valor são passados por cópia e referências são passadas como cópias de ponteiros. Para controlar passagem por referência explícita:

- **`ref`:** a variável deve ser inicializada antes da chamada. A função pode ler e alterar o valor original.
- **`out`:** a variável não precisa ser inicializada antes, mas **obrigatoriamente** deve receber um valor antes do método terminar.
- **`in`:** passa o valor por referência para evitar custo de cópia de structs grandes, mas garante **imutabilidade** (somente leitura).

```csharp
static void Incrementar(ref int valor) => valor++;

static bool TentarDividir(int a, int b, out int resultado)
{
    if (b == 0)
    {
        resultado = 0;
        return false;
    }
    resultado = a / b;
    return true;
}
```
