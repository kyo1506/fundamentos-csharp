# 03.3: Eventos em C#: O Padrão EventHandler e Notificações Desacopladas

> **Fase 03: Coleções Avançadas, Delegados, Eventos, Generics e LINQ** · Aula 3
> Objetivo: dominar o mecanismo nativo de eventos do C#, entender o padrão `event`, utilizar `EventHandler` e `EventArgs`, e implementar publishers e subscribers desacoplados com segurança contra vazamentos de memória.

---

## 1. O Padrão Publisher / Subscriber

Eventos implementam o padrão de projeto **Observer** (Publisher/Subscriber):
- **Publisher (Emissor):** a classe que detém o estado e notifica quando algo relevante acontece (ex.: "uma matrícula foi concluída").
- **Subscriber (Assinante):** uma ou mais classes interessadas que escutam o evento e reagem (ex.: disparar e-mail, registrar auditoria, atualizar painel).

A palavra-chave `event` em C# funciona como um modificador de acesso que restringe o delegate subjacente: **apenas a própria classe declarante pode disparar o evento**, enquanto assinantes externos podem apenas adicionar (`+=`) ou remover (`-=`) handlers.

---

## 2. A Convenção Padrão: `EventHandler<TEventArgs>`

No .NET, a convenção oficial dita que eventos devem usar `EventHandler<TEventArgs>`:
- O primeiro parâmetro é `object? sender` (quem disparou o evento).
- O segundo parâmetro herda de `EventArgs` e carrega os dados do evento.

```csharp
// 1. Dados do evento herdando de EventArgs
public class MatriculaRealizadaEventArgs(Guid matriculaId, string nomeAluno, decimal valorPago) : EventArgs
{
    public Guid MatriculaId { get; } = matriculaId;
    public string NomeAluno { get; } = nomeAluno;
    public decimal ValorPago { get; } = valorPago;
}

// 2. Publisher
public class GerenciadorMatriculas
{
    // Declaração do evento com convenção padrão
    public event EventHandler<MatriculaRealizadaEventArgs>? MatriculaRealizada;

    public void ConcluirMatricula(Guid id, string aluno, decimal valor)
    {
        Console.WriteLine($"[Processando matrícula de {aluno} por R$ {valor:N2}]");

        // Disparo seguro com Elvis operator (evita NullReference se ninguém assinou)
        OnMatriculaRealizada(new MatriculaRealizadaEventArgs(id, aluno, valor));
    }

    // Método virtual de disparo protegido (boa prática do .NET)
    protected virtual void OnMatriculaRealizada(MatriculaRealizadaEventArgs e)
    {
        MatriculaRealizada?.Invoke(this, e);
    }
}
```

## 3. Assinando e Reagindo aos Eventos (Subscribers)

Múltiplos assinantes independentes podem se conectar ao mesmo publisher:

```csharp
public class AuditoriaServico
{
    public void AoRealizarMatricula(object? sender, MatriculaRealizadaEventArgs e)
    {
        Console.WriteLine($"[AUDITORIA]: Matrícula {e.MatriculaId} para {e.NomeAluno} registrada.");
    }
}

public class EmailServico
{
    public void AoRealizarMatricula(object? sender, MatriculaRealizadaEventArgs e)
    {
        Console.WriteLine($"[EMAIL]: Enviando recibo de R$ {e.ValorPago:N2} para {e.NomeAluno}.");
    }
}

// Conexão na Composition Root:
var gerenciador = new GerenciadorMatriculas();
var auditoria = new AuditoriaServico();
var email = new EmailServico();

gerenciador.MatriculaRealizada += auditoria.AoRealizarMatricula;
gerenciador.MatriculaRealizada += email.AoRealizarMatricula;

// Quando o publisher executa, ambos os subscribers são notificados automaticamente!
gerenciador.ConcluirMatricula(Guid.NewGuid(), "Juliana", 450m);
```

## 4. Cuidados com Vazamento de Memória (Memory Leaks)

Como um evento mantém uma referência forte para o objeto assinante via delegate, se o publisher tiver uma vida útil muito longa (ex.: serviço singleton) e o subscriber for efêmero, o Garbage Collector **não conseguirá coletar o subscriber**:

```csharp
// Sempre remova a assinatura quando o assinante não for mais necessário:
gerenciador.MatriculaRealizada -= auditoria.AoRealizarMatricula;
```
Em aplicações de longa duração, prefira implementar `IDisposable` para cancelar assinaturas ou utilizar o padrão Weak Reference quando aplicável.
