# 03.1: Generics em C#: Classes, Métodos e Restrições de Tipo

> **Fase 03: Coleções Avançadas, Delegados, Eventos, Generics e LINQ** · Aula 1
> Objetivo: dominar tipos genéricos em C#, compreendendo como o CLR cria especializações de tipo em tempo de execução sem boxing, e aplicar restrições avançadas com a cláusula `where`.

---

## 1. O que são Generics e por que existem?

Antes dos tipos genéricos (introduzidos no C# 2.0), coleções usavam `System.Collections.ArrayList`, armazenando tudo como `object`:

```csharp
// Abordagem antiga (legada e perigosa):
var lista = new System.Collections.ArrayList();
lista.Add(10);           // Causa Boxing de int para object (Heap)
lista.Add("Texto");      // Permite tipos inconsistentes!
int item = (int)lista[1]; // InvalidCastException em tempo de execução!
```

Com **Generics**, o compilador e o runtime garantem **segurança de tipo estrita (type safety)** e **performance máxima** sem alocações desnecessárias:

```csharp
var lista = new List<int>();
lista.Add(10); // Sem boxing, alocado direto no array interno de int
// lista.Add("Texto"); // Erro em tempo de compilação!
```

## 2. Classes e Métodos Genéricos

### Classe Genérica
```csharp
public class Resultado<T>
{
    public bool Sucesso { get; }
    public T? Valor { get; }
    public string? Erro { get; }

    private Resultado(bool sucesso, T? valor, string? erro)
    {
        Sucesso = sucesso;
        Valor = valor;
        Erro = erro;
    }

    public static Resultado<T> Ok(T valor) => new(true, valor, null);
    public static Resultado<T> Falha(string erro) => new(false, default, erro);
}
```

### Método Genérico
```csharp
public static class Utilitarios
{
    public static void Trocar<T>(ref T a, ref T b)
    {
        (a, b) = (b, a);
    }
}
```

## 3. Restrições de Tipo (Type Constraints com `where`)

As restrições informam ao compilador quais capacidades o tipo genérico `T` deve possuir:

| Restrição | Significado | Exemplo |
|---|---|---|
| `where T : class` | `T` deve ser um tipo por referência (classe, interface, delegate) | `where T : class` |
| `where T : struct` | `T` deve ser um tipo por valor não anulável | `where T : struct` |
| `where T : notnull` | `T` não pode ser anulável | `where T : notnull` |
| `where T : new()` | `T` deve possuir um construtor público sem parâmetros | `where T : new()` |
| `where T : NomeBase` | `T` deve herdar da classe especificada | `where T : EntidadeBase` |
| `where T : IInterface` | `T` deve implementar a interface especificada | `where T : IComparable<T>` |

### Exemplo Completo de Repositório com Múltiplas Restrições
```csharp
public interface IEntidade<TId>
{
    TId Id { get; }
}

public class RepositorioGenerico<TEntity, TId>
    where TEntity : class, IEntidade<TId>, new()
    where TId : notnull, IEquatable<TId>
{
    private readonly Dictionary<TId, TEntity> _itens = new();

    public void Salvar(TEntity entidade)
    {
        ArgumentNullException.ThrowIfNull(entidade);
        _itens[entidade.Id] = entidade;
    }

    public TEntity? ObterPorId(TId id) =>
        _itens.GetValueOrDefault(id);
}
```

## 4. Como o CLR Executa Generics por Baixo dos Panos

- **Para tipos por referência (`string`, classes):** o CLR compartilha o mesmo código de máquina nativo para todas as especializações (`List<string>`, `List<Aluno>`), pois internamente todos são apenas ponteiros de 8 bytes (em 64-bit).
- **Para tipos por valor (`int`, `decimal`, structs):** o JIT compila uma versão nativa especializada sob demanda para cada tipo (ex.: `List<int>` tem sua própria cópia de máquina, `List<double>` tem outra). Isso elimina qualquer custo de boxing e garante acesso contíguo em memória.
